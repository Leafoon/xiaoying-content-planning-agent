# 开发复盘

首先按任务要求检查了工作区，并在写代码前生成 `docs/implementation-plan.md`。实现时选择标准库 SQLite 与线程超时封装，减少离线工程的运行依赖。四类工具统一返回 `ToolResult`，因此失败、部分成功和超时都能进入同一条观察路径。

一次实现调整是把 `low_cost` 和 `fast` 作为模型可选择的变体，而不是在引擎里强制改写参数。这样 Mock 和 Real 共用相同动作接口，预算和截止时间的决策依据也进入 Trace。SQLite 唯一约束解决了重复保存和重跑的一致性问题。

复审阶段发现并修复了几个演示代码常见缺口。请求内容现在会和 `task_id` 绑定，只有补全 `NEEDS_INFO` 的缺失字段可以续跑。工具终态和观察记录在同一事务中写入，保存方案使用原子 `INSERT OR IGNORE`，崩溃遗留的 `RUNNING` 步骤会被转成可审计失败并恢复。步骤计划也会记录工具级预计耗时，Real-like 客户端契约测试确认真实模式和 Mock 共用同一执行引擎。

仍可改进的方向包括为长时间工具使用进程级隔离、接入结构化指标和更细的部分成功素材合并策略。真实服务端的端到端回归仍依赖 API Key。这些不影响当前离线闭环和验收范围。
