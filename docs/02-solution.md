# 技术方案

`AgentRunner` 是唯一的执行引擎。每一轮把请求、当前计划摘要、步骤历史和上一次工具观察交给 `ModelClient`。模型返回 `Decision`，引擎校验工具、依赖和调用上限后通过 `ToolRegistry` 执行，再写入 SQLite 并进入下一轮。引擎没有固定的四工具串行脚本，Mock 策略和 Real 模型均可在估算失败后选择替代方案。

Mock 策略以可审计条件实现动态决策。例如预算超限时改用 `low_cost`，截止时间不足时改用 `fast`，可重试的素材失败会调整变体后再次检索。Trace 的 `mode` 字段明确区分 `mock` 与 `real`，只记录决策理由摘要，不记录隐藏思维链。

SQLite 使用 `(task_id, step_id)` 和 `task_id` 唯一约束。保存方案在事务内使用原子插入，重复保存返回原 ID。工具终态和工具观察也在同一事务内落库。失败续跑时成功步骤仍在库中，后续决策可从步骤结果恢复上下文。
